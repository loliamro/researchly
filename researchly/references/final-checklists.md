# Final Checklists

**Owns:** the self-critique pass and the pre-delivery QA checklists for every deliverable type.
**Use when:** before delivering any substantial output (research answer, review, report, paper
section, critique), or when the user asks "check this before I submit".
**Don't use when:** the user wants a full substantive review of someone's work
(`peer-review-and-critique.md`). This file is a final gate, not a review method.

Run **A. Self-critique pass** on every substantial output, then the matching checklist (B–F).
Fix what fails; if something can't be fixed, say so in the Limitations note. Don't show the
checklist to the user unless they ask; show the result (fixes made, remaining caveats).

## A. Self-critique pass (always)

Re-read the draft as a skeptical reader, in five passes:

1. **Did I answer the actual question?** Compare it with the user's request word by word: scope,
   format, length, audience, deadline. Fix any drift.
2. **Is every claim earned?**
   - Each factual claim has a source I opened, or carries a tag (`Unverified`, `[CITATION NEEDED]`).
   - The strength of each claim matches its evidence (shows / suggests / claims).
   - No number, citation, quote, or name came from memory without a check.
3. **What would a critic attack first?** Name the weakest point. Strengthen it, qualify it, or
   disclose it.
4. **What is missing?** Counterevidence, an alternative explanation, an obvious option, a
   stakeholder, a limitation, a date or version.
5. **Is it usable?** Answer first; headings say something; no filler or AI-sounding padding
   (`editing-and-polish.md` §7); consistent numbers and terms; length fits the purpose.

If a pass reveals a **knowledge** gap rather than a writing gap, go back and research it (or flag
it) instead of papering over it.

## B. Research output checklist (deep-research-modes)

- [ ] Mode stated (quick/standard/deep) and appropriate to the risk
- [ ] Bottom line first, with a confidence tag
- [ ] Every R3 claim meets its minimum evidence or is explicitly downgraded
- [ ] Counterevidence searched (standard/deep) and reported
- [ ] Sources independent where it matters (no single-origin echo)
- [ ] Time-sensitive facts dated; search date stated
- [ ] Fact vs. inference vs. recommendation clearly separated
- [ ] Limitations and open questions listed
- [ ] References complete: every [n] resolves; no placeholders or ranges

## C. Literature review checklist

- [ ] Question and inclusion/exclusion criteria stated
- [ ] Search documented (databases, strings, dates, counts); review type labelled honestly
- [ ] Duplicate reports of the same study linked
- [ ] Findings extracted from full texts for central claims (or limitation stated)
- [ ] Quality / risk of bias appraised with a named tool where appropriate
- [ ] Synthesised by theme; agreements, disagreements, and reasons explained
- [ ] Gaps supported by the search, not asserted
- [ ] PRISMA counts reconcile (systematic/scoping)
- [ ] Citation style consistent (APA 7 unless specified)

## D. Academic writing checklist

- [ ] Core claim or contribution stated early and clearly
- [ ] Each paragraph: one idea, a claim-type topic sentence, integrated evidence
- [ ] Methods replicable; results complete (effect sizes, CIs, n); nulls reported
- [ ] Discussion interprets rather than repeats results; limitations are specific
- [ ] Causal language matches the design; hedging is calibrated
- [ ] Abstract matches the body; word limits met
- [ ] Terminology and abbreviations consistent; figures and tables referenced and self-contained
- [ ] No invented data, approvals, citations, or declarations; placeholders clearly marked
- [ ] Venue, instructor, or funder template and AI-use policy followed

## E. Report QA checklist

**Purpose and audience**
- [ ] Title and executive summary state the conclusion and the ask
- [ ] The executive summary stands alone, is ≤ 1 page, and adds no new information
- [ ] Written for the stated reader's knowledge and decision

**Content**
- [ ] Each finding: headline sentence + evidence + source + confidence
- [ ] Recommendations trace to findings, with owner, timing, cost or impact where relevant
- [ ] Options compared on explicit criteria; alternatives fairly represented
- [ ] Risks with likelihood, impact, and mitigation; assumptions listed
- [ ] Limitations stated

**Numbers and visuals**
- [ ] The same number is the same everywhere (summary, body, tables, charts)
- [ ] Units, bases, periods, and sources on every table and figure
- [ ] Percentages vs. percentage points correct; calculations re-checked
- [ ] Charts honest (no truncated axes or misleading scales) and readable without colour

**Form**
- [ ] Headings informative; numbering and cross-references correct
- [ ] Consistent style, tense, terminology, and spelling variety
- [ ] References complete in one style; appendices referenced
- [ ] Version, date, author, and distribution on the cover (formal reports)

## F. Citation & integrity checklist

- [ ] Every in-text citation is in the reference list and vice versa
- [ ] No fabricated or unverified references presented as real; unverifiable ones flagged
- [ ] Quotes exact, attributed, with page or locator; paraphrases not too close to the source
- [ ] Secondary citations marked; preprints updated to the version of record where available
- [ ] Retracted or predatory sources removed
- [ ] AI-use disclosure included if the policy requires it (drafted from what was actually done)

## G. Delivery note

End substantial deliverables with a short note (2–5 lines):
- What was done (mode, sources, date of search, if relevant).
- What the user must verify or supply (placeholders, `Unverified` items, data, approvals).
- Main limitations.
